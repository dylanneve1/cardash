# CarDash

A Material 3 Expressive launcher for Android car head units.

Built for a Jancar/Rockchip RK3326 unit running Android 11 (API 30),
32-bit `armeabi-v7a` only — which rules out most modern launchers.

## Why it looks like this

- **No AndroidX, no Compose, no Gradle.** Plain framework views compiled
  with `aapt2` → `javac` → `d8`. The APK is 25 KB and contains zero
  native code, so ABI is a non-issue.
- **Material You on Android 11.** Dynamic colour is an Android 12
  framework feature. This generates the tonal palettes itself from
  `WallpaperManager.getWallpaperColors()` (API 27+, no permission
  needed), using CIE LCh as a stand-in for HCT. Change the wallpaper,
  the whole UI re-themes.
- **Expressive shape + motion.** Tiles cycle through a family of corner
  treatments rather than all being the same rounded box, containers
  rotate through the primary/secondary/tertiary roles, and touch gets a
  spring overshoot instead of a fade.
- **Google Sans Text, bundled.** Google Sans is SIL OFL 1.1 since late
  2025, so the real face ships in the APK instead of being hopefully
  requested from the platform. The full family is 2.2 MB per weight for
  8,211 glyphs; these are subset to Latin/Latin-1/Latin Extended-A plus
  punctuation, which is 47 KB per weight. `assets/fonts/OFL.txt` is the
  licence.
- **Dark only.** A bright surface reflected in a windscreen at night is
  a safety problem, not a preference.
- **Offline.** Nothing in it makes a network request.

## Build

    ./build.sh          # -> cardash.apk

Requires an Android SDK with build-tools **35.0.0 or newer**. The 34.0.0
`d8` NPEs under JDK 21.

## Install

    adb install -r cardash.apk

Then Settings → Apps → Default apps → Home app. The stock launcher stays
installed; switching back is the same two taps.

Long-press any tile to reassign it.

## Car data

The vehicle strip (fuel, coolant, RPM, door warnings) stays hidden until
something actually reports. Two pluggable sources behind one interface:

| Source | Hardware | Gives you |
|---|---|---|
| `ObdSource` | ELM327 Bluetooth dongle (~EUR 10) | RPM, speed, coolant, fuel (PID `012F`, optional on Toyota) |
| `JancarSource` | canbox on the harness (~EUR 30-60) | doors, boot, handbrake, reverse, fuel |

OBD-II has **no PID for door state** — that lives on the body multiplex,
so doors need the canbox. Where both can report a field the canbox wins,
since it reads the cluster's own value.

`JancarSource` is wired but **unproven**: the unit it was written on has
no canbox, so the real broadcast actions and extra keys could not be
observed and Jancar publishes no SDK. It therefore logs every intent it
receives under the tag `CarDash/CAN`. Fit a box, watch logcat, drop the
real keys into the `KEY_*` constants. Until then it reports nothing and
the UI simply hides the strip rather than inventing zeros.

## Tests

    ./test.sh

Covers the ELM327 reply parser on a plain JVM — spaced and unspaced
replies, echo left on, `NO DATA`, `SEARCHING...`, truncated frames, and
a reply for the wrong PID. Clone adapters are unreliable enough that a
confident wrong number is worse than no number.

## Screenshots

`screenshots/` is generated by `tools/render.py`. These are **mockups,
not device captures** - but not eyeballed ones: every dp value is copied
from the layout code, the density matches the head unit (160dpi base,
186 override), and the colours come from running the app's own `M3`
class on the JVM. Layout, proportion and palette are faithful; the
rasteriser and the app icons are stand-ins.
